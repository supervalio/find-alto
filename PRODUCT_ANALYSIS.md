## 1. Что это за продукт

**Find Alto** — редакционный гид по независимым fashion-дизайнерам из стран СНГ. Не интернет-магазин, а discovery-платформа: пользователь путешествует по гео-навигации (Страна → Город → Категория → Вещь), изучает профили дизайнеров, читает истории брендов и находит уникальные вещи с культурным контекстом.

**Аналог:** Lonely Planet, но для мира локальной моды.

### Ключевая проблема
Найти действительно интересного локального дизайнера, не тратя часы на поиск и проверку. Информация есть — но она разрознена по Instagram, Telegram-каналам и сарафанному радио. Find Alto решает это редакционным отбором.

### Целевая аудитория
- Путешественники, которые покупают вещи вместо сувениров
- Любители независимой моды
- Стилисты и fashion-журналисты

## 2. Ключевые функции

### Публичная часть (6 страниц)

| Страница | Что делает |
|----------|-----------|
| **Главная** `/` | Логотип, список стран с фото, concept stores, fashion events |
| **Страна** `/armenia` | Фото, описание, список дизайнеров, магазинов и событий |
| **Город** `/armenia/yerevan` | Категории товаров с количеством, рекламные блоки |
| **Категория** `/armenia/yerevan/clothing` | Сетка вещей с ценами, список дизайнеров категории |
| **Дизайнер** `/designer/loom-weaving` | Профиль: фото, био, история, «Почему местные это носят», галерея вещей, контакты |
| **Вещь** `/item/voluminous-cardigan` | Фотогалерея, цена (локальная + USD), материал, история, блок о дизайнере |

### Админ-панель (7 страниц, на русском)

Полный CRUD для всех сущностей: страны, города, категории, дизайнеры, вещи, рекламные блоки. Загрузка фото через drag & drop с превью. Дашборд со статистикой.

### Дополнительно
- Хлебные крошки на всех страницах
- SEO-метаданные (title, description) для каждого маршрута
- Рекламные блоки с привязкой к стране/городу
- 404-страница
- `/api/upload` — API загрузки фото в Supabase Storage

## 4. Уникальные архитектурные решения

### 4.1 Гибридная загрузка данных: Supabase + Seed

Страницы сначала пробуют загрузить данные из Supabase, при ошибке или отсутствии — прозрачно переключаются на seed-данные из `src/lib/guide-data.ts`. Это даёт:

- **Устойчивость:** сайт работает даже если БД недоступна
- **Грациозная деградация:** Supabase-клиент возвращает no-op mock при отсутствии переменных окружения — страницы не падают, а показывают "not configured"
- **Быстрая разработка:** не нужно наполнять БД чтобы увидеть результат

```typescript
// src/db/index.ts — ленивая инициализация
// @neondatabase/serverless загружается только при первом запросе,
// чтобы Vercel не падал на этапе сборки
function getDb(): Promise<Db> | Db {
  if (_db) return _db;
  const { drizzle } = await import("drizzle-orm/neon-serverless");
  ...
}
```

### 4.2 Ленивая инициализация БД-драйвера

`@neondatabase/serverless` загружается динамически (`await import()`) только при первом реальном запросе — это решает проблему падения Vercel build на этапе сборки статических страниц. Vercel не пытается резолвить нативные зависимости неона.

### 4.3 No-op прокси для graceful degradation

И Supabase-клиент, и Drizzle-подключение при отсутствии переменных окружения возвращают Proxy-объекты, которые не крашат приложение, а возвращают осмысленные ошибки. Это позволяет коду работать в любых условиях:

```typescript
// src/lib/supabase.ts
function createNoopClient(): SupabaseClient {
  // Возвращает цепочку прокси, которая всегда резолвится в { data: null, error }
}
```

### 4.4 Гео-навигация через динамические маршруты

Next.js App Router с вложенными динамическими сегментами:
```
/[country]/[city]/[category]
```
Каждый уровень добавляет контекст, хлебные крошки строятся автоматически из URL. Никакого состояния — чистая маршрутизация.

### 4.5 Админ-панель без аутентификации

Осознанное решение для раннего этапа: админка открыта, доступ через прямой URL. Упрощает контент-менеджмент на старте. Безопасность компенсируется RLS-политиками Supabase.
