## Слайд 2. Проблема

### Что не так с поиском локальной моды?

- 🔍 **Информация разрознена** — Instagram, Telegram, сарафанное радио
- ⏱️ **Часы на поиск** — чтобы найти одного стоящего дизайнера, нужно перелопатить десятки аккаунтов
- ❌ **Нет верификации** — непонятно, кто реально производит, а кто перепродаёт
- 🌍 **Нет географической привязки** — «я еду в Ереван, где купить локальное?»

### Почему это важно

Рынок независимой моды СНГ растёт на 15-20% в год, но у дизайнеров почти нет каналов для выхода на международную аудиторию. Find Alto — мост между локальными брендами и глобальным потребителем.

---

> 🎤 *Спикер:* «Проблема не в отсутствии информации — её слишком много. Пользователь тонет в Instagram-аккаунтах и не понимает, кому можно доверять. Find Alto решает это редакционным отбором: мы добавляем только бренды с собственным производством, узнаваемым стилем и реальными мастерскими, которые посетили лично. Это не агрегатор — это curated experience.»

---

## Слайд 3. Решение

### Как Find Alto решает проблему

**Гео-навигация:** Страна → Город → Категория → Вещь
Пользователь путешествует по карте, а не по бесконечной ленте.

**Редакционный контент:**
- История каждого дизайнера — как создавался бренд
- «Почему местные это носят» — культурный контекст
- Каждая вещь с описанием материала и сторителлингом

**Для дизайнера:** бесплатный профиль с фото, контактами и галереей вещей
**Для путешественника:** готовый гид: куда идти, что покупать, сколько стоит

**Никакой коммерции:** не магазин, не маркетплейс. Нет корзины, нет «купить». Только discovery.

---

> 🎤 *Спикер:* «Ключевая фишка продукта — гео-навигация. Ты едешь в Тбилиси, открываешь Find Alto и сразу видишь: дизайнеры в этом городе, их категории — одежда, обувь, аксессуары — и конкретные вещи с ценами. Плюс stores и events. Как путеводитель, но для моды. И важно: это не коммерческий проект. Мы не берём комиссию, не продаём. Мы соединяем.»

### Связи между компонентами

- **Публичные страницы** → Supabase (первично) → Seed data (fallback)
- **Админ-панель** → Drizzle ORM → Supabase PostgreSQL
- **API /upload** → Supabase Storage
- **Graceful degradation:** если Supabase недоступен → no-op прокси, страницы не падают

---

> 🎤 *Спикер:* «Архитектура построена вокруг гибридной загрузки данных. Каждая страница сначала пробует Supabase — это живая база. Если БД недоступна или переменные окружения не заданы, страница прозрачно переключается на seed-данные — статический JSON с 4 странами и их описанием. Это даёт устойчивость: сайт работает всегда, даже если инфраструктура временно недоступна. Отдельно отмечу ленивую загрузку драйвера БД — он инициализируется только при первом запросе, чтобы Vercel не падал на этапе сборки статических страниц.»

## Слайд 9. Что узнал — инсайты и сложности

### Главные инсайты

| Инсайт | Контекст |
|--------|---------|
| **Graceful degradation важнее идеальной работы** | Сайт не должен падать. No-op прокси для Supabase и Drizzle спасли деплой |
| **AI ускоряет, но не заменяет архитектурное мышление** | Решения о структуре данных, маршрутизации и fallback-стратегии принимал я |
| **Дизайн-систему нужно фиксировать сразу** | 4 итерации палитры: тёплая → холодная → зелёный акцент. Каждая требовала рефакторинга |
| **Vercel build — это отдельный челлендж** | Ленивая загрузка нативных зависимостей спасла деплой |

### С какими сложностями столкнулся

| Проблема | Как решил |
|---------|----------|
| **Vercel build падал** с ошибкой | Ленивый `import()` для `@neondatabase/serverless` — драйвер загружается только при первом запросе, а не на этапе сборки |
| **Русские названия в базе** ломали английскую версию | Правка данных в Supabase через REST API + переключение `nameRu` → `nameEn` в коде |
| **AI-генерировал «ужасный дизайн» (слова заказчика)** | Итеративный подход: 3 варианта → отказ → удаление. Дальше — точечные правки по фидбеку |
| **Смесь русского и английского на публичных страницах** | Системный аудит всех файлов, переключение всех `nameRu` → `nameEn`, удаление «Volume 01» и «Chapter One» |
| **4 страны показывались как 1** | Supabase возвращал только Армению → исправил логику: merge DB + seed, недостающие докидываются |

---

> 🎤 *Спикер:* «Главный инсайт курса: продакшен — это не только код. Это CI/CD, graceful degradation, SEO, адаптивность, обработка ошибок. AI отлично помогает с генерацией, но архитектурные решения — моя зона ответственности. Три итерации дизайна, миграция с SQLite на Supabase, fix Vercel build — каждый этап учил чему-то новому.»
